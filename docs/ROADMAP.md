### 1.1 已确认的高风险问题

**① 任意文件读取 + 上传（最高）**
`server.py:312` 的 `search_kwargs.update(extra_params)` 在 `file`/`url` 装好之后**无过滤覆盖保留键**；`PicImageSearch.utils.read_file()`（utils.py:74-78）接受路径字符串直接 `open()`。正对照（canary 越过读文件、走到 HTTP 响应解析阶段，文件被 multipart 上传至 `yandex.com`）+ 负对照（不存在路径 `FileNotFoundError`），**本机与 us-01 两处独立复现**。服务以 **root** 运行、绑 `0.0.0.0`、公网可达。

**② cookie / proxy 配置即失效**
`_parse_cookies()`（:113-122）/ `_parse_proxy()`（:104-111）产出 `dict`，而 `Network.__init__` 只吃字符串 ⇒ `'dict' object has no attribute 'split'`（network.py:52）、`no attribute 'url'`（network.py:58）。README:94 恰把这两个变量写成官方解法 —— **指向死路**。`HTTP_PROXY`/`HTTPS_PROXY`（:249）无需用户配置即命中。

**③ cookie 无域，凭据发往任意域名**
`httpx.AsyncClient(cookies={...})` 把 cookie 发给 `untrusted.invalid`、`api.trace.moe`、`notyandex.com` 等无关域；换 `httpx.Cookies()` 显式 `domain="yandex.com"` 后只发目标域与其子域。**每次新建 `Network` 仍泄露**（astra 用真实 `Network` 复验：`fresh_Network → untrusted.invalid` 仍带 cookie）。
**关键推论：只修②会让 cookie 开始进入原先被构造失败挡住的路径 ⇒ ③必须与②共同发布。**
两个限定：`domain=` 也匹配子域；`Cookies.set` 不自动带 `Secure`。故"限域有效"成立，**"这一行已完成凭据隔离"不成立**。

**④ 条件性认证绕过**
`main.py:15` 无条件放行路径 `/`**且不分方法**；`main.py:70` 降级分支把 Streamable HTTP 挂在 `/`；`Route("/")` 只管 GET/HEAD ⇒ **POST 落到 MCP 路由**。ASGI 直连实测：无票 `initialize` + `tools/call` 返回 **200 并拿到工具输出**；对照 `/messages/` 正确 401。触发前提是启动时 SSE 构造失败。**当前线上不满足该前提**（匿名 `/sse`、`/mcp` 均 401），但踩到即全敞。

**⑤ 结果映射与参数缺陷**
- `episode=0` 被 `server.py:190` 真值判断吞掉（`Time: 0.0s - ?s`）
- `To=0` 被 `server.py:197` 显示成 `?`
- **SauceNAO 丢 `similarity`（:181-187 不读）与 `author_url`**。**注意：`url` 没丢** —— `server.py:171-172` 的通用分支在所有引擎分支**之前**已输出 `item.url`（v2 此处写错，见附录 B）
- `limit=-1` → `showing top -1`，实际 2 条；`limit=0` 仍真发一次请求
- **公示参数无效**：`cutBorders` 传了不生效（真名 `cut_borders`，False 时"不再携带该参数"）；Yandex 的 `rpt`/`cbir_page` 被库内写死覆盖；SauceNAO 的 `output_type` 上游固定 `json_loads`

### 1.3 病因：可验证的表述

1. **没有明确的受测依赖组合。** 依赖不锁版本，也没声明支持哪套组合；接口误用与失效的兼容分支因此能进到发行物里。
2. **发行前没有协议级门禁。** 0 测试、无 CI。`TODO.md` 的「代码层面验证」不是验证。
3. **部署产物不可复现。** uvx 缓存 + 无锁 + 9 份副本；部署脚本管的单元名（`image-search.service`）与线上真实单元（`image-search-mcp.service`）不一致，**跑一遍不更新真正的服务**。

## 二、设计原则

> **这些是原则，不是实施条目。**每条原则都必须在下文有对应**任务落点**，否则不算数。

1. **不建全面兼容层，建可执行的行为契约**：直接测现有入口 `_search_image_logic`，第三方用真类、外部 HTTP 走 MockTransport，断言**具体请求字段与结果映射**。
2. **「唯一 import 点」不是验收标准。** 把错误的 dict 传参搬进适配层照样能通过 —— 契约靠行为测试证明。
3. **每条修复配一条能自动抓住它的回归，且必须反向测试。反向测试要能排除错误实现**（见批次 1 验收修订）。
4. **候选依赖升级必须跑同一套测试**；另设**低频在线抽验**（离线 fixture 发现不了远端改版）。
5. **Yandex 优先**，但不为它牺牲边界安全。
6. **不安装 `main` 的未发布代码**；**不承诺自修上游缺陷**。
7. **健康 ≠ 能搜。**
8. **不把"新建 client"当万能隔离手段** —— 但独立无凭据下载 client 仍是有效边界。

### 批次 1 · 安全与边界

**本批结束要能准确地说：「已知高风险路径已关闭，且有测试守住」—— 不是「目录更整齐但认证洞还在等第四批」。**

| # | 改什么 | 怎么验（含反向） | v3 修订 |
|---|---|---|---|
| 1-1 | `extras` 严格校验：顶层必须对象、键名白名单（**取自 0-1**）、类型/范围，**拒绝保留键 `file`/`url`** | **拒绝必须发生在文件读取与网络创建之前** —— "没有出站请求"不足以证明没读文件。覆盖：顶层 null、数组、键值对数组、保留键、未知键、错误类型 | 白名单改为引用 0-1 |
| 1-2 | 删静默降级：应用构造失败 → **非零退出** | 故障注入**只让 `transport="sse"` 失败、保留真实 fallback**。实测：把所有 `http_app` 调用都模拟失败，**在当前有漏洞的旧代码上也能通过**（`ALL_HTTP_APP_CALLS_FAIL_EXIT 1 uvicorn_called=False`）；只让 `sse` 失败才真正触发降级（`SSE_ONLY_EXIT None uvicorn_called=True http_app_calls=[{'transport':'sse'},{'path':'/'}]`） | 加退出码非零 + 限定故障注入范围 |
| 1-3 | 根路径豁免收窄：独立 `/healthz`、仅 GET/HEAD | 匿名 POST `/` 返回 405 是**必要条件而非充分条件**（当前正常 SSE 应用本就 405）。需补正向：`/healthz` 匿名 GET/HEAD 可用、HEAD 无响应体、**健康检查不产生外部 HTTP 请求**、非健康路径不继承豁免、非健康方法不继承 GET 的豁免、授权客户端协议端点仍可用 | 补正向验收 |
| 1-4 | cookie/proxy 按契约传字符串，**且**完成凭据隔离 | **必须定义三件事（缺一不可）**：(a) **jar 接入点** —— `Network(cookies=CookieJar)` 会 `AttributeError: 'Cookies' object has no attribute 'split'`；可行窄方案是"真实 `Network` 不接收无域 cookie 字符串，在请求前把限域 jar 装到它暴露的真实 `AsyncClient` 上"；(b) **凭据归属** —— 当前只有一个全局 `IMAGE_SEARCH_COOKIES`，无引擎归属；若实现成"给同一份全局 cookie 换 domain"，A 引擎凭据仍会发给 B 引擎。须定配置结构、旧值处理、错误提示；(c) **用户图源用无引擎凭据的独立下载 client** —— 仅限域不够，**同域图源仍会带凭据**。验收须含正向（正确引擎收到正确凭据）+ 反向（不只是还原 dict，还要故意恢复"合法字符串＋无域 cookie"） | 补 jar 接入点、凭据归属、无凭据下载 client |
| 1-5 | 缺有效 token 拒绝启动 | **验收命令必须用 `--sse`** —— 实测 `['--host','0.0.0.0']` 仍走 stdio（`stdio_called=True uvicorn_called=False`）。行为矩阵：stdio 不需 HTTP token；HTTP 模式缺/空白 token 启动失败；匿名 HTTP 须显式开发模式；**开发模式只能绑回环，不能因开了开关就允许 `0.0.0.0`/`::`**；有效 token 能正常起和调用 | 修正验收命令 + 补矩阵 |

## 五、安全下载器契约（1-6 的前置设计）

> v2 在这里只有五个问句，不足以让实施者做对。**未定项不得开工。**

**a. 实际接管入口**
已接入引擎中明确调用上游 `download(url)` 的：`EHentai`（engines/ehentai.py:89-90）、`BaiDu`（engines/baidu.py:98-99）。需写清**在何处替换为安全下载**、再把 bytes 交给引擎的 `file` 参数。
**Yandex 首次 URL 搜索应继续由 Yandex 抓图** —— 不为"统一下载"让服务器无差别下载所有 URL；本地下载只发生在**明确允许的兜底路径**。
**无法安全接管的路径本批明确拒绝**，而不是继续透传。

**b. URL 与地址策略**
允许的 scheme、端口、是否拒绝 URL 内嵌用户名密码；被拒的非公网地址范围（IPv4、IPv6、**IPv4 映射 IPv6**）；DNS 同时返回公私地址时怎么办；**DNS 失败不得退回未校验连接**；**公网 IPv6 正例必须能通过**（不能把"覆盖 IPv6"实现成"一律拒绝 IPv6"）。

**c. DNS 到实际连接的绑定，以及代理策略**
"解析→确认公网→普通 `client.get(url)`"仍可能二次解析。需规定**实际连接使用已验证的目的地址**，同时保留正确的 Host、TLS SNI 与证书校验。
**代理是本项关键遗漏**：若代理代替本机解析目标域名，本机 DNS 校验不能证明代理最终连到哪里。三选一并写明：用户图源下载**不继承**环境/引擎代理；或走**具有相同目的地址约束的受控代理**；或**暂不支持的代理组合直接拒绝**。不能留给"按契约传代理字符串"解决。

**d. 重定向规则**
关闭不受控的自动跟随；规定最大跳数；**每跳重新校验** URL、地址与凭据策略；明确 HTTPS 降级到 HTTP 的行为。

**e. 预算的数值、单位与计数位置**
明确最大字节数、重定向次数、**下载总期限（覆盖 DNS、连接、重定向、读取）**。`Content-Length` 只可提前拒绝，**不能代替实际流式计数**；无 `Content-Length` 与分块响应同样限制；明确压缩响应按哪一层限大小（避免解压后突破）；超限**立即停止消费**；决定是拒绝空体与不支持类型，还是允许任意 bytes。

**f. 生命周期与失败行为**
超限、重定向拒绝、取消、超时后，响应与 client 都应关闭；不留挂起连接，**不绕回不安全的旧路径**。

**g. 测试观测到哪一层**
MockTransport 适合验证 HTTP 语义，**不做真实 DNS 与连接**。"DNS 校验与连接目标一致"的测试必须观察**受控 resolver／连接后端实际收到的目的地址**，不能只在 MockTransport 里断言 URL 字符串。**并加正例**，避免"所有下载都拒绝"通过安全测试。

## 六、明确不做

| 不做 | 理由 |
|---|---|
| **不安装上游 `main`** | 会吃下 `httpx`→`httpx2` 迁移。**但"不能取任何 commit"过头** —— 小范围回移植单个修复与整套安装不是同一风险范围 |
| **不承诺自修 Bing** | 签名解密、请求重建、解析样本、异常处理放进适配层，维护工作不会消失。保留"小范围回移植 / 受测 fork / 等正式版本"的后续选择。**"容易变成半个分叉"是维护风险，不是单个补丁必然导致；"不支持"与"实验性"最终要选清楚** |
| 不建全面 compat 层 | 撤掉的是"为集中 import、按版本号分支而建的全面兼容层"。**但不要把这次决定扩张成"不能新增任何网络适配代码"** —— 1-4/1-6 完全可能需要很薄的 client 工厂、安全下载模块或出站策略边界 |
| **不把"新建 client"当隔离手段** | 无域 cookie 才是直接原因；重复新建带相同无域 cookie 的 client 仍然泄露。**但独立无凭据下载 client 仍是有效边界** |
| 不把传递依赖塞进 PyPI metadata | 发布包声明兼容范围，生产环境单独锁 |
| 不引入 OAuth / 不重写成框架 | 先修认证覆盖、TLS、最小权限。**"轮换"若只是后续原则，就不要写成本轮承诺**（v2 有此问题，已移出承诺） |
| **不拿"正确性"当性能的挡箭牌** | 共享方案要处理同域不同凭据、可变 headers、代理、生命周期 —— **可控的工程风险，不是永久禁止复用的理由**。先补**最小耗时基线**（落点：2-4 的测试运行时间记录） |
| 不做全引擎能力矩阵 | 先覆盖实际承诺范围 |

## 八、「下一个 level」的验收定义

1. **已知高风险路径关闭且有测试守住** —— 六个洞各有正反测试，且**能排除"删功能式"的假通过**
2. **行为契约可执行** —— 逐引擎断言具体字段；对候选依赖升级跑同一套测试会报警
3. **部署可复现** —— 从锁文件重建跑同一套依赖；单元名/脚本/线上三者一致；有**回滚验证**与**最小发布门槛**
4. **健康可判且不烧配额** —— 存活/就绪/引擎抽验三层分开，且**有消费规则**（抽验失败不触发重启）
5. **错误语义清晰** —— `isError` 正确、区分五类（含"源图抓取失败"）、客户端收不到 traceback、日志脱敏
6. **主引擎兜底** —— Yandex 最多兜底一次，且兜底路径受安全下载边界约束
7. **文档不误导** —— README 每条配置建议都在 CI 里被真实执行过；**行为变更的文档随修复交付**
