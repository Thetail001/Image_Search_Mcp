## 二、门禁与反向测试

**10 条注入，10 条被抓住，且都是干净的断言失败。**

```
$ python tools/reverse_tests/run.py
合计：抓住 10/10
结论：每条注入都被指定的测试抓住，门禁可判定。
```

注入的定义在 `tools/reverse_tests/bugs.py`，每条都写明"对应哪个原始缺陷、
由哪条测试负责抓"。执行器 `tools/reverse_tests/run.py` 做四件事，
少一件反向测试就不成立：

1. 把 `src/` `tests/` `pyproject.toml` 复制到临时目录
2. 在**副本**里做文本注入（不动工作区，避免"忘了还原"）
3. **先验证导入到的是副本里的模块**，再跑测试 ——
   否则跑的还是干净代码，反向测试是假的
4. 要求退出码为 1（断言失败）。**退出码 2（收集错误）/ 5（没收集到）不算抓住** ——
   "跑不起来"和"发现问题"是两件事

### 反向测试自己抓出来的两个问题

第一轮跑出 7/9，两条"没抓住"。查下来两条其实都抓住了，但**方式是超时**：

- `test_slow_trickle_is_stopped_by_total_deadline` 用了 `while True` 造响应，
  总期限失效时测试挂到 pytest-timeout 才结束。更糟的是它当时收的是
  `(DownloadError, httpx.HTTPError, TimeoutError)` 这样一个宽泛异常元组 ——
  等于"只要因为任何原因失败就算通过"。已改成有限响应（80 块 × 30ms）
  并只接受 `DownloadError` 且断言 `reason == "timeout"`，另加一条
  "在预算内的慢响应必须成功"的正对照
- `test_missing_token_refuses_to_start` 直接调 `main()`，而 `main()` 成功时
  会进 `uvicorn.run` 并阻塞。已加 `no_server` 夹具：走到起服务就带着说明失败

两条都从"挂 30 秒 + 一屏超时堆栈"变成秒级干净断言。CI 上"卡住"比"失败"难查得多。
