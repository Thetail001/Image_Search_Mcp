# 配置变更说明

适用于从早期版本升级到当前实现。完整配置示例见 [README](../README.md)。

## HTTP 服务

- HTTP 模式必须设置非空 `MCP_AUTH_TOKEN`；stdio 模式无需此变量。
- 只有 `GET /healthz` 和 `HEAD /healthz` 免认证。根路径、SSE 与消息端点均需要 Bearer 令牌。
- SSE 端点为 `/sse`，消息端点为 `/messages/`。应用构造失败时会终止启动。
- 带 `Origin` 的请求必须匹配 `IMAGE_SEARCH_ALLOWED_ORIGINS`；未配置时拒绝此类请求。
- 匿名调试需显式开启，并且只能绑定回环地址。WebSocket 不受支持。

## Cookies 和代理

优先使用按引擎命名的变量：

```bash
export IMAGE_SEARCH_COOKIES_YANDEX="sid=...; other=..."
export IMAGE_SEARCH_COOKIES_EHENTAI="igneous=...; ipb_member_id=..."
```

旧的 `IMAGE_SEARCH_COOKIES` 仍可与 `IMAGE_SEARCH_COOKIES_ENGINE` 一起使用，后者必须明确指定引擎。未指定归属时，使用该全局配置的搜索调用会被拒绝；服务启动和健康检查不验证引擎凭据。引擎专属变量优先于旧配置。

Cookies 仅发送给对应引擎的域名，且仅通过 HTTPS 发送。无效格式会返回配置错误，错误信息不会回显 Cookie 值。

代理只从 `IMAGE_SEARCH_PROXY` 读取，不再使用 `HTTP_PROXY`、`HTTPS_PROXY` 等通用代理变量。它只影响搜索引擎请求。本机抓图使用独立下载器，不携带引擎 Cookies，也不使用代理。

## 工具调用

- `extra_params_json` 只接受各引擎支持的参数。`file`、`url`、`api_key`、`cookies`、`proxies` 等保留键不能由调用方覆盖。
- TraceMoe 的参数名是 `cut_borders`；`cutBorders` 会被拒绝。
- `limit` 必须是 1–50 的整数，布尔值不被接受。
- Base64 必须合法且非空，解码后不得超过 16 MiB。本地文件路径不被接受。
- EHentai 和 BaiDu 的 URL 输入由本机下载，限制为 8 MiB、15 秒、最多 3 次重定向。非公网地址、HTTPS 降级和压缩内容编码会被拒绝。
- 输入、配置和明确的上游错误返回 `isError=true`。没有匹配结果仍是成功，结构化结果中的 `results` 为空列表。
- 成功结果增加了 `structuredContent`。引擎专属字段仍在文本中，通用字段的完整结构见 README。

## 部署脚本

默认操作单元为 `image-search-mcp.service`，可通过 `IMAGE_SEARCH_UNIT` 指定其他名称。已有单元默认保留；`--replace-unit` 会先备份再替换。

`--reconfigure` 会备份并重写当前目录下的 `.env`，保留脚本未管理的键。已有单元是否读取此文件，应以其 `EnvironmentFile` 为准。

`.env` 按数据读取，支持单行未引用值、单引号值和双引号值。`$VAR`、`$(...)` 与反引号均为字面文本，不能用于引用其他变量或执行命令。多行值需要改为单行格式。新写入的配置和备份使用受限文件权限。

带令牌的部署检查要求 `/messages/` 返回缺少 `session_id` 的 HTTP 400；其他状态会使检查失败。若令牌只写在已有 systemd 单元中，脚本会提示无法执行此检查，需要人工验证。

## 升级后检查

```bash
systemctl status image-search-mcp --no-pager
curl -i http://127.0.0.1:8000/healthz
curl -i http://127.0.0.1:8000/
curl -i -H "Authorization: Bearer $MCP_AUTH_TOKEN" http://127.0.0.1:8000/
```

预期依次为：服务运行、健康检查 200、匿名根路径 401、带有效令牌的根路径 200。最后再从 MCP 客户端执行一次搜索，确认引擎和网络配置可用。
